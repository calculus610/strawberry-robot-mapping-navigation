# 实验室建图与旧占据撤销候选 v1

本次只做静态部署。新入口、新建地图和桌面、桌腿保护效果均待用户现场运行验收。
输出仍是未校准的候选图，`complete` 表示本次处理已完成。

## 在机器人上新建地图

在机器人终端执行这一条命令：

```bash
bash /home/wheeltec/manual_map_lab_cleanup_20261111/start_test.sh
```

1. `mapping_session.py` 调用原 `manual_map_postprocess_test/start_test.sh --no-preview`，并绑定这次建图返回的 `SESSION_DIR`。自动清理只使用这个目录。
2. 采集结束后按一次 **Ctrl+C**，等原流程保存本次地图并完成最终的 C 或 D 图。保存阶段会忽略重复的 Ctrl+C。只有本次会话成功保存并产出完整的最终 `enhanced_conflict`（C）或 `enhanced_scatter`（D），才会启动离线清理。
3. 清理阶段再按 **Ctrl+C** 可取消本轮清理，原会话已保存的图仍可使用。清理成功后会生成独立候选目录，并尝试在机器人桌面打开本次 `comparison.png`。

成功后终端会打印候选目录、变化格数和对照图路径：

```text
CLEANUP_CANDIDATE_SAVED=/home/wheeltec/maps/manual_lab_cleanup/<源会话>_<时间>_<随机后缀>
CHANGED_CELLS=...
COMPARISON=.../comparison.png
```

在新入口后加 `--no-preview` 可关闭最终对比图的桌面打开请求，仍会生成 `comparison.png`。它不关闭原建图 RViz，也不取消原入口对机器人桌面环境的检查。
`--max-seconds` 控制离线清理的超时，默认 600 秒。`--protect-roi` 与 `--review-roi` 也可传给新入口，行列须对应本次原尺寸 PGM。失败、超时或中断时保留原会话产物，候选目录只在处理完整后提交。

## 重新处理已保存的旧会话

`run_cleanup.sh` 只用于对已保存的 C/D 会话重新执行离线清理。该入口无法启动建图。显式指定要重处理的会话目录：

```bash
bash /home/wheeltec/manual_map_lab_cleanup_20261111/run_cleanup.sh /完整源会话路径
```

截图中 726 帧、0 个变化格来自旧会话的离线重处理。新入口与新地图的验收仍待现场运行。

## 输出含义

| 文件 | 含义 |
| --- | --- |
| `map.pgm`、`map.yaml` | 独立候选地图；只允许黑 0 转灰 205 |
| `before/map.pgm`、`before/map.yaml` | 所选最终 C/D 图的精确副本 |
| `comparison.png` | Before / After / Changes。橙色为本轮撤回格，有变化时附局部放大图 |
| `withdrawn_mask.pgm` | 255 为实际撤回格 |
| `protected_mask.pgm` | 用户显式保护区；默认全零，不代表算法没有其他保护 |
| `changes.csv` | 实际变化的零基 PGM 行列、支撑数及原因 |
| `cells.csv` | 每个输入黑格的撤回或保留原因 |
| `supports.csv` | 各高度三维支撑的命中、保护、三站回波见证 |
| `report.json` | 输入/代码/输出 SHA、阈值、全部封口帧统计、耗时及本进程峰值 RSS |

候选和 before 各有同名 `map.pgm`，YAML 字节、坐标、分辨率与源图相同。
黑转灰表示撤回旧占据，不表示已证明可通行。已有白格和灰格不改变。
如果输入 D 已把某个桌腿变灰，本版不会恢复它；必须先检查 before 图。

## 算法与保护边界

1. 复核完成会话、A005/C/D 的哈希、投影 PCD 与原图几何。输入都以只读方式访问。
2. 两遍顺序读完整封口 `observations.bin`，包括晚于原投影快照的帧。
   原生树重复发布不算新的命中；未知命中时间的原生点保持占据。
3. 逐格保留原生点以及观测的三维子区支持，不按整块面积或像素外观删除。
   某格全部支持都通过撤销条件后，才允许该格变灰。
4. 任何更晚且可能重合的端点，包括相邻 XY 格、邻近高度及移动期间的端点，
   都更新最后可能命中并重置原撤销票。没有回波不计为自由。
5. 仅在低速静止观测中，以同位置、同高度、更远真实回波收集撤销证据。
   近共线前景回波否决该帧的模糊穿越。桌下射线不能用于撤销上方桌板。
6. 至少三站，两两相隔至少 0.30 m、观察方位 20°、时间 1 s；新命中使票数重新累计。
7. 额外保留至少 5 帧、跨越 2 s 的持续支撑。这是保护结构的启发式，
   也可能保留长时间站立的人及重复噪点；本版没有人物/桌子语义识别。

当前实验阈值：5 cm XY 输出，10–100 cm 高度范围保持原样；
射线距离上限 5 m、近端保护 0.50 m、回波终点前保护 0.15 m；
空间/高度容差各 15 mm，假设射线余量 7 mm、端点余量 3 mm，
支撑子区半径与上述余量都从容差内扣除。时间余量 20 ms。
静止判定使用相邻记录位姿：平移不超过 0.02 m/s、角速度不超过 0.01 rad/s，持续至少 0.5 s。
这些是初版保守工程参数，不是测得的传感器误差上界，不代表清理已可靠。

即使真实桌体仍存在，薄杆附近的射线与位姿误差也可能造成误判断。
不能把有限回波条件宣称为严格证明。需要你对照桌面/腿位置验收；误删时先停用候选并反馈坐标。
有本次地图上的明确桌体范围时，可用 `--protect-roi 行起,行止,列起,列止` 指定保护矩形，可重复传入。坐标取自本次原尺寸 PGM，零基、末端不含。保护矩形内保留原占据。`--review-roi` 使用同样格式，仅用于分区统计。

## 由用户执行的观察

保持桌子固定。临时障碍离开后，从不同位置补扫其旧位置，每站停稳数秒，并确认有更远背景回波。结束时按一次 Ctrl+C，等本次对照图生成。

先检查桌面和桌腿是否被撤回，再查看残影减少的范围。若零变化，可查看 `report.json` 中的 `motion_rejected_frames`、`stationary_frames`，并结合各格保留原因和站位票数判断撤回证据是否充足。可反馈 `comparison.png`、`report.json` 和 `changes.csv`。

## 资源、依赖与停用

机器人使用 `/usr/bin/python3`（需要 Python 3.10+、NumPy、PyYAML、Pillow）。
离线清理入口把 BLAS/OMP 设为单线程。`PYTHON_BIN` 仅用于指定离线清理的兼容解释器；新编排器固定使用 `/usr/bin/python3`，原建图保持自己的启动环境。不自动安装依赖。
三份旧工具读取器放在 `baseline_tools/` 并固定 SHA；新代码不依赖修改旧部署文件。

本版默认 600 s 超时，`--max-seconds` 接受大于 0 且不超过 3600 的秒数。
Linux 限制离线清理进程虚拟地址空间最多 1536 MiB（继承更低限制时按更低值），
提交前还检查峰值 RSS 不超过 1536 MiB。设限不是实测；整机运行状态与实际峰值由用户验证。
二维格、三维支撑、帧点数和配对块均有容量上限，超过即报错，不交付缺失地图。

停用时，直接运行原建图入口 `bash /home/wheeltec/manual_map_postprocess_test/start_test.sh`。如已在外部查看器打开候选，重新打开原会话 `session.json` 中 `final_map` 指定的地图即可。
新增目录和独立候选可保留供追溯。候选仅保存和预览，导航地图由用户选择。
