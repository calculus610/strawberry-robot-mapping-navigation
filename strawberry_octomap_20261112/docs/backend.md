# OctoMap 后端

本实验节点继承 ROS 2 Humble `octomap_server` 2.3.1，链接普通 XYZ 共享库。官方点云回调、三维射线、按帧体素去重和占据概率更新直接参与建图。现有 FAST-LIO 提供扫描及扫描末光心位姿。`cloud_in` 的点坐标和同戳 TF 必须以该光心为原点，目标坐标系的 Z 轴及零面由实验地面参考确定。

## 高度和地图语义

默认体素和二维像素都是 5 cm。高度带为固定参考面以上 `[0.10, 1.25)` m，共 23 个体素层。每个 XY 列有任何已知占据即标黑，23 层都已知自由且无占据才标白，其余标灰。OctoMap 压缩后的叶子按覆盖范围参与计算。投影用整数体素键对齐边界，格子数超过一百万时在分配前拒绝该次投影。

关闭地面分类，并保留投影高度带之外的有限端点供三维更新。有效距离仍由 `sensor_model.max_range` 约束。低于高度下限的占据体素不参与二维结果。标准 OctoMap 从扫描光心沿实际回波方向遍历体素，使用自己的终点和空闲更新规则。旧版本的近端 0.50 m、回波前 0.10 m 空闲证据保护及 A–E 后处理在此后端没有对应步骤。杆、桌面和人员残影仍要用现场观测验收。

## 发布和保存

后端随输入以最高约 1 Hz 频率完整投影，实验入口将二维图发布到 `/strawberry_octomap/map`，使用可靠且 transient-local 的 QoS。首次发布含已知格的地图时打印 `OCTOMAP_MAP_READY`，此后定期记录接收的扫描时间戳、树节点数及二维格数。普通建图回调不准备三维可视化或整树 ROS 消息。保留原只读服务按需查询二进制树或完整树。树内存随观测范围和密度变化，投影格数限制只约束二维数组。

`/strawberry_octomap/finalize` 冻结新的点云更新，立即用最新树重投影并保存 `map.pgm`、`map.yaml`、`octree.ot` 和 `metadata.json`。首版从入口按一次 Ctrl+C 发起此流程。没有已知格时保存失败。成功元数据最后提交，包含投影时间戳、坐标系、高度、版本和 OctoMap 树的内存估计，估计值独立于进程 RSS。PGM 使用官方 Nav2 MapIO。YAML 保留同一张地图的原点精度，并用 `free_thresh: 0.19` 使灰度 205 重载后仍为未知。

`publish_web_map` 默认关闭。启用时，同一张二维图额外以可靠且 transient-local 的 QoS 发布到 `/map`。启用前需部署独立的 Web 建图会话识别并确保 `/map` 发布者互斥。首版保存由入口的 Ctrl+C 触发，Web 的保存按钮不控制这次会话。
